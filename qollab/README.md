# QPlace on Qollab: QAOA pod placement

A Kubernetes pre-drain question, posed as a quantum experiment: can the pods on the node being drained be placed elsewhere?

The instance is the "greedy trap" from QPlace M2:

- Greedy places 1 of 2 pods.
- The exact solver places both.

The demo runs one QAOA circuit, with angles trained offline, on the backend you select. It then decodes and verifies the samples.

| | |
|---|---|
| Qubits | 3 (one per eligible pod→node pair) |
| Algorithm | QAOA, p = 2, angles trained locally (exact statevector + COBYLA) |
| Backend jobs per run | exactly 1 (`backend.run`), as IonQ's one-job limit requires |
| Output | greedy and exact baselines, measured shots, feasible and optimal sample counts, **random-guess baseline**, best verified placement |

## Run

- **Qollab:** upload `main.py`, `quantum_demo.py`, `placement_data.py`, `requirements.txt` and `README.md` (not `__pycache__`). Pick the built-in simulator or IonQ, then press Run. Qollab provides `backend` and calls `main()`.
- **Locally:** `python main.py`. This uses Qiskit's `BasicSimulator` and labels the run `LOCAL FALLBACK`.

`placement_data.py` is generated by `scripts/generate_m3_artifacts.py` in https://github.com/edeediong/qplace-k8s. The repository tests check that this demo's circuit and decoding match the main implementation.

Synthetic data only. This is a placement-model experiment, not a safe-to-drain guarantee. Quantum optimality is not proven, and no quantum advantage is claimed. MIT licensed.
